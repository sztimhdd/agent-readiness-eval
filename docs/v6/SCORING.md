# V6.0.0 结果判定说明

本版保留业务 50 分、过程 50 分的计分结构。每题总分 100 分。原通过结果另列，不并入这 100 分。

V6.0.0 是五题选集，不代表六槽能力全集，也不构成六槽正式榜单。所有任务时限为 1800 秒。本版时限与部分原任务设置不同，因此结果不用于复现官方榜单。

## 判定原则

- 按任务对应的原交付合同检查业务结果。
- 过程分按该题适用的过程要求判定。不要用任务完成状态替代证据。
- 分开记录业务分、过程分、原通过结果和总分。
- 只依据实际可见证据打分。公开检查通过不自动代表业务通过。
- 隐藏 F2P 与原 verifier 不在下载包中。管理员需按固定来源链接在受测隔离环境之外单独准备。没有这些材料时，不要声称复现了历史判分。

## 各题边界

| 任务 | 可用公开检查 | 不能据此单独确认的内容 |
|---|---|---|
| Pipeline | 使用真实依赖的公开 pytest 测试 | 超出公开测试覆盖范围的业务正确性，以及历史判分复现 |
| Ansible | `compileall` 语法检查；公开上游测试 | 语法检查不能证明业务通过。原 48 项用例须由独立源判器判定 |
| Inventory408 | `python3 -m unittest discover -s tests` | 公开测试未覆盖的业务要求 |
| Purchase409 | CSV 文件与格式检查 | CSV 格式正确不能证明采购选择正确 |
| Finance | 使用 `openpyxl` 检查公式和缓存值 | 公式或缓存值检查不能单独证明财务业务正确 |

Finance 按本次已有成绩采用的原交付合同判定。三项增强交付检查属于未来改版内容，不作为 V6.0.0 的新增要求。

## 结果报告

逐题报告业务分、过程分、总分、原通过结果、使用的判定材料和未覆盖范围。将公开检查、独立判定与历史结果分开标注。没有判定证据的项目标为未判定，不推算分数。

## 固定过程量表

过程10项各5分：业务理解、状态管理、核心正确性验证、风险与边界验证、验证独立性、最终交付验证、依据与调整、调整闭环、操作边界、交付可信度。每项0=完整证据确认未做或不成立，1=仅动作，2=部分比较且明显缺关键预期，3=有效比较但有限覆盖/未闭环，4=主要充分且有限缺口，5=公开合同范围内充分成立。日志缺失保留pending，不按0或满分填补。耗时、调用数、失败数和thinking不计分。

Pipeline业务=40×F2P通过/64+10×P2P通过/47。其他题沿固定源业务完成度映射至50，原bool另列；仅凭原bool不能反推50分。本包不公开既有私有映射细目，因此没有管理员固定判据时只能报告公开检查结果与未判定项，不能声称复现历史100分。
